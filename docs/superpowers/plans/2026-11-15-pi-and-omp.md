**Goal:** pi and omp users can install a command-line share skill with one line, and the Docs' Agent setup page tells them how, then points them to Plans.

## Facts checked on 2026-11-15

- pi 0.79.6 loads skills from `~/.agents/skills/` (`join(homeDir, ".agents", "skills")` in its package). omp 18.20.0 resolved `skill://herdr` to `~/.agents/skills/herdr/SKILL.md`.
- The published CLIs are npm 0.4.1 and PyPI 0.4.0. Both have `login`, `logout`, `status`, `whoami`, `push` and `pull`, and `push` takes `--ttl-days`.
- `push` prints the link as the first line of stdout and exits nonzero on failure, with the reason on stderr. npm also prints `Expires: …`; PyPI does not.
- During `push`, a line starting `Warning:` means the secret scan flagged the file, in both CLIs (npm: "Warning: secret scan flagged …" on stdout; PyPI: "Warning: <server warning>" on stderr). Their other `Warning:` lines belong to `login` and `--allow-http`.
- The dashboard's Files section has "Revoke file".

```markdown
# Share a file through Veilfile

Veilfile hosts private, expiring file links for AI agents. When you make a file the user needs to see or download, upload it with the `veilfile` command and share the link it prints. The link is unguessable, and it stops working when the file expires.

## When to use this skill

(copied from the MCP skill)

## Before the first upload

Run `veilfile status`. If the shell cannot find the command, tell the user to install it with `npm install -g veilfile` or `pip install veilfile`, then stop. If it fails for any other reason, tell the user to run `veilfile login` in their own terminal, then stop. Never ask the user to paste a key into chat, and never run `veilfile login --print-key`, which prints the key.

## How

1. Run `veilfile push <path>`. To choose how many days the link lasts, add `--ttl-days N`; the server shortens it if the plan does not allow that many.
2. The first line of output is the link. If a line of output, on stdout or stderr, begins with `Warning:`, the secret scan flagged the file: do NOT share the link. Tell the user the upload was flagged, and ask whether to keep it or revoke it in the Files section of their Veilfile dashboard.
3. Otherwise, share the link in one line, with the expiry if the output gives one: `Here is the <kind>: <url> (expires <date>)`.
4. If the command fails, it exits with a nonzero status and prints the reason. Tell the user the reason. A refused file type, a file over 25 MiB and a month with no uploads left are not fixed by retrying.

## Never

- Never upload a file the user did not generate or ask about in the course of the work.
- Never share a link whose upload printed a `Warning:` line.
- Never put the API key in a prompt, a message, or a file. It lives in the CLI's credentials file or the environment, not in text.
```

**The Docs, `backend/docs/pages/agent.md`.** The description becomes "Connect Claude, Codex, Cursor, pi, omp and other agents to Veilfile, with setup for each one and what to do when a secret is flagged." A new section goes after "Other clients" and before "Claude apps":

````markdown
## pi and omp

pi and omp can use Veilfile through the `veilfile` command-line tool and a skill, with no MCP setup.

1. Install the CLI with `npm install -g veilfile` or `pip install veilfile`, and install only one of the two. Then run `veilfile login` once in your own terminal.
2. Install the skill:

```bash
mkdir -p ~/.agents/skills/veilfile
curl -fsSL https://veilfile.com/skills/veilfile/SKILL.md -o ~/.agents/skills/veilfile/SKILL.md
```

Both pi and omp load skills from `~/.agents/skills/`. Start a new session and ask the agent to share a file it made. It runs `veilfile push` and gives you the link. The key stays in the CLI's credentials file, and the agent never sees it.

See [Plans](/plans/) for how many uploads each plan allows and how long its links last.
````

**One change from the design:** the design had the omp section say that omp picks up MCP servers already set up for Claude, Cursor or Codex. I left that sentence out. omp's README says it, but I could not test it with Veilfile, and the skill already covers omp.

## Global Constraints

- The voice rules: complete sentences, semicolons only between independent clauses, no em dashes or exclamation marks, American spelling. Headings and labels are exempt. The facts must hold.
- The skill uses only commands and flags the published CLIs have (above). No `--visibility`, and nothing about teams.
- Agents do not edit `backend/legal/documents/`. Commits are made as `Veilfile <support@veilfile.com>` with `TZ=UTC` and no attribution lines.
- Tests run from `backend/` with `DJANGO_DEBUG=True DJANGO_SECRET_KEY=dev-only-key ../venv/bin/python manage.py test <module>`, and the whole suite once at the end, in the background.

## Review Focus

1. **A missing file in a deploy.** If the skill file is absent, the route answers 404, like `llms_txt`, never 500.
2. **The served copy is the repo copy**, byte for byte, as `text/markdown; charset=utf-8`, so `curl -f` writes exactly the reviewed file.
3. **The skill against the CLIs.** Every `` `veilfile <command>` `` it names is a published command, and both CLIs still mark a flagged push with a line starting `Warning:`.
4. **The Docs page's contents list** shows "pi and omp", and site checks that pin agent.md's headings or description still pass.
